# Preparation - Log Analysis

This is the process of understanding events generated by a computer to identify anomalies such as security threats, application bugs, system performance, or other risks that may impact the organisation.

## Event Correlation

This identifies significate relationships from multiple log sources, such as application logs, endpoint logs, and network logs.
This deals with identifying significant artefacts co-existing from different log sources and connecting each related artefact.

With this information, we can connect the dots of each artefact from the two data sources:

- Source and Destination IP
- Source and Destination Port
- Action Taken
- Protocol
- Process name
- User Account
- Machine Name
Event correlation can build the puzzle pieces to complete the exact scenario from an investigation.

# Preparation - Tools and Artifacts

1) **COMPARE BY HASH**: Always compare the artefacts by their hashes. It is a common practice to verify if the artefacts are expected as it is.
    - We can do that in powershell as follows: `Get-FileHash -Algorithm SHA256 <ARTEFACT NAME>`

2) **TOOLSET**: To analyse Windows artefacts such as Windows Event Logs and Sysmon Logs, we will use the following tools: `EvtxEcmd`, `Timeline Explorer`, `SysmonView` and `Event Viewer`.
To analyse the provided packet capture, we will use the following tools: `Wireshark` and `Brim`.

## EvtxEcmd & Timeline Explorer

EvtxEcmd is a command-line tool which parses Windows Event Logs into different formats such as CSV, JSON, XML, etc. It can be used in conjunction with Timeline Explorer.
Timeline Explorer is a GUI-based tool that functions as a data filtering and navigating application to ease incident responded in handling raw data.
1) First, we need to convert the EVTX logs into CSV using EvtxEcmd.
    - Powershell Command line (first change directory to the location of EvtxEcmd): `.\EvtxECmd.exe -f 'C:\Users\user\Desktop\Incident Files\sysmon.evtx' --csv 'C:\Users\user\Desktop\Incident Files' --csvf sysmon.csv`
2) Second, we feed it into Timeline Explorer: FILE > OPEN > CSV_FILE

## SysmonView

This is a Windows GUI-based tool that visualises Sysmon Logs.
1) First, we must export/save the log file's contents into XML via Event Viewer.
2) Then feed it into SysmonView: FILE > IMPORT SYSTEM EVENT LOGS

# Initial Access - Malicious Document

_FOLLOW THIS PROCEDURE TO AID WITH INVESTIGATION_

1) Start with the events generated by Sysmon
2) EvtxEcmd, Timeline Explorer, and SysmonView can interpret Sysmon Logs
3) Follow the child processes of WinWord.exe
4) Use filters such as ParentProcessID or ProcessID to correlate the relationship of each process
5) We can focus on Sysmon events such as Process Creation (Event ID 1) and DNS Queries (Event ID 22) to correlate the activity generated by the malicious document.

# Initial Access - Stage 2 execution

Investigation guide:

1) Autostart execution reflects explorer.exe as its parent process ID
2) Child processes of explorer.exe within the event timeframe could be significant
3) Process Creation (Event ID 1) and File Creation (Event ID 11) succeeding the document execution are worth checking


# Initial Access - Malicious Document Traffic

Investigation guide for network log analysis:

1) Brim and Wireshark can be used to investigate the packet capture
2) Find network events related to the harversted domains and IP addresses.
3) Sample Brim filter for this investigation: `_path=="http" "<malicious domain>"`

# Discovery - Internal Recconnaissance

Investigation guide

1) Find network and process events connecting to the malicious domain.
2) Find network events that contain an encoded command
3) We can use Brim to filter all packets containing the encoded string
4) Look for endpoint enumeration commands since the attacker is already inside the machine

We may refer to out cheatsheet for brim to quickly investigate the encoded traffic with the following filters:

- To get all HTTP requests related to the malicious C2 traffic: `_path=="http" "<replace domain>" id.resp_p==<replace port> | cut ts, host, id.resp_p, uri | sort ts`

# Privilege Escalation - Exploiting Privileges

Investigation guide

1) Look for events executed after the successful execution of the reverse socks proxy tool.
2) Look for potential privilege escalation attempts, as the attacker has already established a persistent low-privilege access.
